## 1 - Verdict on the two source documents

**The idea is pertinent. The execution plan, as written, is not applicable here — and the
user was right to be skeptical.**

Separating the two things:

- **The diagnosis remains valid and has grown.** Reversa injects the `description` of **every** model-invoked skill into the context of each request. This is real, measurable, and has grown: the report measured 49 skills / ~3,677 tokens on 07/30; today there are **65 skills / ~4,987 tokens** of permanent load. Reducing this by marking phase agents as `disable-model-invocation: true` is a legitimate optimization, and the mechanism (keep `description`, just add the flag) is correct.

- **The execution plan was written against another repository.** The session that produced the HANDOFF worked on an **installed copy** of Reversa in `/workspaces/CHUPA-CABRA/reversa-otimizacao`, alongside mattpocock's skills (`pocoyo-skills`). That is why the document assumes a world of **two synchronized trees** (`claude-skills` + `agents-skills`), points to scripts and paths that **do not exist here**, and counts 49 skills. **This repository is the SOURCE of Reversa** — single `agents/` tree — and the two trees only come into existence on the **end user's machine**, generated by the installer (`lib/installer/writer.js` -> `cpSync(..., { recursive: true })` for `.claude/skills` or `.agents/skills`, per `lib/installer/detector.js`).

Conclusion: **we leverage the reasoning, discard the playbook.** The plan below rewrites the steps for the single-tree source, which in practice **eliminates half the work and all the risk of divergence between trees** (parity becomes structural, not manually maintained).

## 4 - Decision taken — Scenario B

**The skills that remain model-invoked are the flow entry points.** The criterion: a skill only remains model-invoked if the **model has a reason to reach it on its own** — that is, if the user triggers it by describing the intent in natural language, without typing the slash. Everything else is reached by the orchestrator reading the `SKILL.md` and becomes user-invoked.

The frontmatter `role` closes the list unambiguously: the **8 `role: orchestrator`** plus `reversa-agents-help` (`role: help`).

**The 9 that remain model-invoked:**

| Skill | role | Why it stays |
| --- | --- | --- |
| `reversa` | orchestrator | The word `reversa` alone activates (promise from `CLAUDE.md`) |
| `reversa-new` | orchestrator | "new project", "forward" via natural language |
| `reversa-forward` | orchestrator | Forward flow |
| `reversa-migrate` | orchestrator | "I want to migrate this system" |
| `reversa-autonomous` | orchestrator | Autonomous mode |
| `reversa-refactor` | orchestrator | "refactor", "optimize the code" |
| `reversa-debugger` | orchestrator | "there is a bug", "debug" |
| `reversa-docs` | orchestrator | "document this system" |
| `reversa-agents-help` | help | "which agents exist" (only debatable member — see note) |

**The other ~56 become user-invoked** (`disable-model-invocation: true`): phase agents (`reversa-scout`, `reversa-architect`, `reversa-reviewer`), the `reversa-pricing-*`, the `reversa-debugger-*` (`-fix`/`-debate`/`-graph`), the `reversa-docs-*`, the refactor specialists (`reversa-optimize`, `reversa-simplify`, `reversa-prune`...) and the renderers. They remain reachable via typed `/name` and by the orchestrator reading the `SKILL.md`.

- **Cost:** 9 model-invoked - ~668 permanent tokens -> savings of **~4,319 tokens (-86%)**.
- **Note on `reversa-agents-help`:** it is the only debatable member — if you prefer the catalog to only appear when the user types `/reversa-agents-help`, move it to user-invoked and the savings increase slightly. Kept in B to allow "show me the agents" in natural language.

> Warning: **Why not Scenario A ("only `reversa`"):** `CLAUDE.md` promises activation by the word `reversa` alone, but the other flows (migrate, document, debug) would lose natural language routing — the user would have to know and type each `/name`. The extra savings (~596 tokens) does not pay for the product behavior regression.

## 5 - Revised plan — single tree, 8 steps, framework working at each one

> **The rule governing everything:** Reversa working today is worth more than any token savings. When in doubt between "saves more" and "definitely does not break", choose not to break. One commit per step.

**Step 0 — recompute the axis.** Run the measurement script, list the 65 skills, classify each as entry-point (stays) or phase agent (gets marked). Close the section 4 list with the user. *Empty milestone commit.*

**Step 1 — functional baseline.** Since the source does not have `.reversa/`, install Reversa in a temporary directory (`npx reversa init` in a sandbox, or via `bin/reversa.js`) and record the behavior of `/reversa`, `/reversa-agents-help`, `/reversa-forward` **before** any changes.

**Step 2 — fix invocation sites (before the marks).** Invert precedence to **read the `SKILL.md` and execute in the current context** as the primary path. The only site that today activates by name without an alternative is `step-01-first-run.md:63`; the rest already have the dual pattern — standardize all. Reinstall and repeat the Step 1 test: **identical behavior**. *Commit.*

**Step 3 — mark ONE skill.** `reversa-scout` (the most critical: first one the orchestrator calls and target of the fixed site). Add only `disable-model-invocation: true` to the frontmatter — **keep the `description`**. Install, test end to end (`/reversa` reaches Scout? `/reversa-scout` directly still works?). If it fails, **stop and revert**. *Commit.*

**Step 4 — mark the rest.** Script on the **single `agents/` tree** (no x2, no inter-tree lockstep), skipping the entry-points list, idempotent. Review `git diff --stat`. *Commit.*

**Step 5 — the Codex mark (`agents/openai.yaml`).** Create in each skill: `policy.allow_implicit_invocation: false` in user-invoked; only `interface:` in model-invoked. Since the installer copies the skill folder recursively, these files **reach the user automatically** — but **confirm this by installing** and checking that the `openai.yaml` appears at the destination. *Commit.*

**Step 6 — rewrite user-invoked `description` fields.** Reduce to a human one-line summary, **without triggers** (`Use when...`, `type "/..."`). In the model-invoked entry-points, **do not touch** — there the triggers are the auto-invocation mechanism. *Commit.*

**Step 7 — the verifier (this is where Reversa surpasses the reference).** **The script already exists in the folder:** `evolucao/reducao-de-tokens/verify-invocation.py` (106 lines, functional). It already checks, per tree:

1. Every skill has `agents/openai.yaml` with `interface.display_name` + `short_description`.
2. Lockstep **within the skill**: `disable-model-invocation: true` iff `openai.yaml.policy.allow_implicit_invocation: false`.
3. User-invoked `description` without model trigger (`Use when...`, `type "/..."`).

Adaptations needed for the source:
- **Remove the `filecmp` block for "tree equality"** (lines 81-98): it was made to compare `claude-skills` x `agents-skills` on an installed machine; in the single-tree source it is dead code.
- **Add the installer invariant** (replaces that equality): a test that installs in a temporary directory and confirms that the flag and `openai.yaml` **traverse** to `.claude/skills` and `.agents/skills`. Here parity is structural (one source), so what needs a guard is the **transport**, not the equality.
- **Move the script to `scripts/verify-invocation.py`** in the repository (today it lives only in this evolution folder) and reference it in the Step 8 document. Optional: rewrite in Node to match `lib/`.

It already exits with code 1 on any violation -> serves as a direct CI gate. *Commit.*

**Step 8 — the written policy.** A short doc (`docs/` or `agents/reversa/references/`) declaring: the axis (every skill is user- or model-invoked, no third state); the two marks in lockstep within the skill; the reach rule (orchestrator reads the `SKILL.md`, does not activate by name); the `description` rule; the measured cost (19,948 -> target chars, ~4,987 -> target tokens); and the pointer to the Step 7 verifier. *Commit.*

**Definition of "broken" (aborts delivery):** the orchestrator cannot reach a user-invoked agent - a `/reversa-*` that worked stopped working - the word `reversa` alone stopped activating (Scenario B) - the flag or `openai.yaml` did not traverse on installation.

## 6 - The invariant that the single source gives us for free

The HANDOFF spent three steps defending "the two trees have to remain identical". **Here that problem does not exist:** there is one source, and the installer replicates. What deserves a guard now is the **installer preserving the marks when copying** — and that is a 20-line test (Step 7.4), stronger than manual discipline because it fails noisily in CI. This is literally the point where Reversa surpasses the reference cited in the report.
